# Review checklist — agent 产出审查清单

> 本文件是**审查顺序、清单、风险分级与记录模板的唯一事实源**。任何审查都必须按第 1 节顺序执行，并产出第 5 节的审查记录；只写一段「看起来没问题」不视为完成审查。

## 1. 审查顺序

1. **范围** — 先看改动文件清单，确认没有越界；范围不对就直接打回，不必往下读。
2. **验收证据** — 核对任务卡里的命令是否真的跑过、输出是否通过；「测试通过」不等于「正确」。
3. **逻辑** — 逐文件读 diff，判断实现是否匹配目标，而非是否「看起来合理」。
4. **影响面** — 沿调用方、依赖方向、跨进程边界检查隐含假设是否被破坏。
5. **最后才读 agent 的说明文字** — 摘要是线索，不是证据。

## 2. 清单

### 范围

- [ ] 改动文件均在任务卡「范围」内，无顺手重构、格式化、无关依赖升级。
- [ ] 单个 diff 可独立回滚；未混入多个目标的改动。
- [ ] 新增文件有明确归属，临时文件与调试代码已清理。

### 正确性

- [ ] 实现匹配目标描述的状态，而非仅完成了某个动作。
- [ ] 边界条件（空值、并发、失败路径、超时）被处理。
- [ ] 未破坏未读取文件中的隐含假设；调用方与被调用方一并核对。
- [ ] 错误处理方式与项目现有惯例一致。

### 测试

- [ ] 测试用例由人给定或独立设计，不是与实现共享同一误解的自证式测试。
- [ ] 测试真的会失败（存在能捕获回归的断言），而非恒真断言。
- [ ] 验收命令完整执行，输出可复现；构建与运行时依赖一并验证。
- [ ] 关键路径有人工设计的负向用例。

### 安全与副作用

- [ ] 无未授权的外部动作（push、部署、发消息、网络请求、删除、覆盖）。
- [ ] 无凭据、密钥、个人信息被写入代码或日志。
- [ ] 依赖变更经过确认，来源可信。
- [ ] 跨进程 / 跨语言边界（HTTP、IPC、DLL、序列化格式）保持兼容。

### 可维护性

- [ ] 命名、分层、注释风格与代码库一致。
- [ ] 没有为通过测试而引入的补丁式特判、硬编码、跳过标记。
- [ ] 改动量与问题复杂度相称；异常膨胀说明可能在无限重试中跑偏。

## 3. 风险分级

agent 处理高危改动与低危改动的速度和自信相同，审查强度必须由风险决定：

| 级别 | 典型改动 | 审查强度 |
| --- | --- | --- |
| 低 | 文案、注释、文档、局部样式 | 快速扫 diff + 构建通过 |
| 中 | 业务功能、接口新增、依赖升级 | 全量清单 + 测试证据 + 影响面核对 |
| 高 | 支付 / 鉴权 / 数据迁移 / 并发 / 删除 / 构建与部署配置 | 逐行审查 + 人工设计的边界用例 + 第二人复核 + 灰度或预发验证 |

## 4. 打回信号

出现以下任一情形，停止合并并让 agent 重做或转人工：

- 改动范围越界且未说明；
- 验收命令未执行、被跳过，或输出与宣称不符；
- 同一失败重试痕迹明显（反复试探式补丁、diff 异常膨胀）；
- 测试与实现明显共享同一误解；
- 出现未经授权的外部动作或不可逆变更；
- 目标本身被发现有歧义 —— 先由人澄清规格，再重新委派。

## 5. 审查记录模板

审查结论必须按以下结构输出，缺项视为审查未完成：

```
任务卡：（链接或编号）
改动范围：（文件清单）
验收命令与结果：（命令 + 通过 / 失败）
发现的问题：（逐条）
结论：合并 / 打回 / 转人工
规格偏差回写：（是否更新模板或项目约定）
```
